## Purpose

通过用户指定的 Typesafe 官方 JEV 1.13 做持续移动贪吃蛇的真实方向决策，保持模型请求和游戏循环独立，并将选择、概率、响应时间与是否生效作为可观察记录。

## ADDED Requirements

### Requirement: 真实结构化决策
runner SHALL 支持 Typesafe 直连与显式选择的 OpenRouter，不自动回退。接口使用 state/questions/choice 契约，只允许返回定义中的方向并校验字段类型。概率合计不等于 1 SHALL 只作为诊断信息，不阻止提交有效方向，且原始概率不得被自动归一化。不得把聊天解析、固定规则或模拟结果标为 JEV。

#### Scenario: 概率合计为 0.99 或 1.01
- **WHEN** 模型返回有效方向，单项概率字段合法但合计为 0.99 或 1.01
- **THEN** 原样保存概率并提交模型选择的方向，记录合计提示，不因此中断对局或替换方向

#### Scenario: 未配置密钥
- **WHEN** 没有当前 provider 对应的 TYPESAFE_API_KEY 或 OPENROUTER_API_KEY
- **THEN** 明确显示未配置，真实 runner 拒绝启动，不创建虚假 JEV 对局

### Requirement: 当前局面与在途请求
runner SHALL 使用服务端当前已提交的实际局面请求模型，目标固定为该局面的紧接着一次移动；每次最多一个在途请求，每个实际 tick 最多询问一次。接纳后等待实际 tick 推进才再次询问。返回后带原始目标和摘要提交，禁止预测多步、填充未来队列或重绑旧观察。

#### Scenario: 结果已过时
- **WHEN** 请求返回时目标 tick 已过或局面摘要失效
- **THEN** 该结果不生效，记录原因，再基于最新状态决策；游戏持续运行

### Requirement: 模型结果可追溯
系统 SHALL 保存实际模型版本、选择、概率、置信度、请求耗时及最终接纳/生效结果。失败记录明确原因，不返回假成功，也不切换其他模型。

#### Scenario: API 失败
- **WHEN** 当前服务商返回错误或格式不符合契约
- **THEN** runner 暴露错误，并通过受保护通道标记对局中断；历史保留已提交过程

#### Scenario: 真实错误与终局相邻发生
- **WHEN** 已发生终局，但模型请求抛出真实 HTTP、网络或响应校验错误
- **THEN** 错误仍明确输出并使 runner 非零退出，不将其视为成功或主动取消；只有与实际 abort reason 相同的错误才可归类为终局取消

#### Scenario: 请求在结束前未完成
- **WHEN** 对局结束时模型请求尚未返回
- **THEN** runner 记录请求开始及取消、对应观察步和目标步、实际等待时长，不虚构模型决策或将等待时间标为纯推理耗时
