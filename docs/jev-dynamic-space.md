# 历史 V14：动态分支与进食依据

当前默认入口已更新为 [V15 吃果后续路检查](jev-growth-space.md)。本页保留 V14 的历史定义与边界，不修改旧存档。

V14 对应模型请求 `dynamic-space-v14`，在 V13 的合法选项和静态事实之外新增 `dynamicFacts`、`analysisLimits`、`dynamicSemantics`。字符图、完整有序身体、障碍、食物、真实历史与实际模型响应继续存档。它借鉴食物路线的完整身体模拟和增长后检查，仍由 JEV 每次选择一个方向。

## 两类动态事实

`dynamicFacts[direction].trap` 检查首方向之后的完整身体变化，最多 8 步，全部步数都包含首步：

| status | 含义 |
| --- | --- |
| `proven_trap` | 所有合法续路均在检查范围内结束且没有下一步；`moves` 是其中最长合法移动步数。只有完整分支耗尽才成立。 |
| `horizon_reached` | 找到一条可走满窗口的续路；不表示窗口之外安全。 |
| `unknown_after_apple` | 某条续路吃到已观察苹果，正确增长后还有即时出口；新苹果未知，动态检查在此停止。 |
| `node_limit` | 分支尚未检查完；`moves=null`，不判死或判安全。 |
| `board_complete` | 找到在 `moves` 步内吃当前苹果并填满棋盘的续路；只有 `moves=1` 才是本步直接获胜。 |

`dynamicFacts[direction].apple` 在该首方向下寻找当前苹果的到达方式，最多 32 步：

| status | 含义 |
| --- | --- |
| `route_with_exit` | 找到一条可执行进食候选，增长后至少还有一个合法下一步。保存候选长度、下一步合法出口数及静态尾部连接，不发送整条路线。 |
| `route_wins` | 找到吃到当前苹果时填满棋盘的候选路线，步数可能大于 1。 |
| `no_route_with_exit_found` | 当前搜索没找到带出口的进食候选；不等于苹果不可达。 |
| `no_apple` | 当前没有苹果，无此项搜索。 |

`termination` 进一步说明找到候选、有限图检查结束、深度限制、节点限制或不适用。遇到吃果后零出口的到达状态，搜索还会检查其他身体排列下的进食方式，不能用第一条坏路线否定全部路线。

食物搜索以 `已走步数 + 16 × 曼哈顿距离` 排序探索，但每次移动都用完整身体和游戏规则验证。这个权重只决定预算内的探索顺序，不是动作评分，不把任何方向指定给模型。它不是保证最短的 A*；找到的长度不是全局最优距离。

## 计算与未知边界

默认 `analysisLimits={trapDepth:8,appleDepth:32,maxNodesPerSearch:2048}`。所有本步合法方向独立使用相同预算；困死与进食搜索分别计数。食物搜索同时限制累计加入的状态、队列与去重集合，避免只限制展开数量而让待检查队列无限膨胀。节点只包含轻量身体几何，不复制请求历史、完整 MatchState 或搜索树。

不调用引擎 RNG、不猜测新苹果，不把吃果后的无增长未来当成真实未来。困死分析只在吃到当前苹果后立即无出口时可继续给确定终止结论；否则停止为未知。食物候选也只验证到达和即时出口，不能保证之后安全。星星到期与 `stateHash` 过期请求拒绝仍由原服务执行。

深度和节点预算是可见的分析范围，不改变对局的胜负条件或最长运行时间。`JEV_DYNAMIC_ANALYSIS=false` 可显式切回 V13，历史 V14 仍按保存内容查看；配置错误直接报错，不静默降级。

## JEV 的取舍与执行

Prompt 要求优先处理胜利和确定的困死证据，再比较增长后有出口的进食候选，并允许为身体腾位暂时远离苹果。静态面积和曼哈顿距离作为辅助信息；实际无果返回历史用于识别重复行为，在没有已知进食候选时结合有限续路证据考虑改变身体排列。

动态结果只作为候选事实。所有本步合法方向继续提供，模型即便选择已证明危险方向也不被程序替换。只剩一个方向仍记录真实 API 结果；无合法方向沿用原终局。原始概率不补零、不归一化，不引入超时自动走路。

V14 schema 校验观察、静态事实和动态字段的结构、互斥状态及预算范围；不会为了读取每条历史请求再次执行动态搜索。分析正确性由独立局面、完整身体移动回归和内存压力检查验证。协议解析通过本身不构成路线证明。
