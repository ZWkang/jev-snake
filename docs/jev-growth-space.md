# V15：吃果后的持续退路检查

V15 修复 V14 在吃当前苹果且存在即时出口时提前结束动态检查的问题。已知反例：8afee24c 第323→324步的下方实际三步必困，却被记录为“一步吃果、有一个出口”；487a3f48 第77→78步的右方六步必困，却被记录为“两步吃果、有两个出口”。

原始 V14 定义、构造器、解析器与历史正文保持不变。默认新的实时请求为 `growth-space-v15`；`JEV_DYNAMIC_ANALYSIS=false` 仍显式使用 V13。

## 吃果后如何判断

搜索正确更新整条有序身体，吃到已观察苹果时增长一格、尾巴保留。之后不猜测新苹果，而在“之后不再增长、尾巴尽早释放”的乐观几何中继续检查。

若连这个较宽松条件下所有合法续路都耗尽，实际继续增长也不会更早释放身体格。但还必须排除一种例外：额外增长可能在死亡前先填满棋盘获胜。如果剩余空格数不大于乐观分支可继续的最长步数，就保留 `unknown_near_win`，不作死亡证明。

因此确定的 `proven_trap` 不依赖某个新苹果位置，也没有读取实际 RNG。反过来，乐观条件下有路不能证明实际新苹果及额外增长后也安全。

## 模型收到的字段

`analysisLimits` 为 `trapDepth=8`、`appleDepth=32`、`postAppleDepth=8`、`maxNodesPerSearch=2048`。

`dynamicFacts[direction].trap`：

| status | 含义 |
| --- | --- |
| proven_trap | 全部分支已耗尽，若涉及吃果后的乐观放宽也已排除额外增长先获胜；moves包含当前首步。 |
| horizon_reached | 有一条不跨未知后续增长的窗口见证，不证明窗口之外安全。 |
| optimistic_horizon_reached | 有一条吃当前果后不再增长的窗口见证；明确有条件。 |
| unknown_near_win | 无法排除额外增长先填满棋盘；不是已经找到胜路，moves为null。 |
| node_limit | 未完成检查，moves为null。 |
| board_complete | 找到吃当前苹果并满盘的续路；只有moves=1才是当前一步获胜。 |

`dynamicFacts[direction].apple`：

- `route_with_optimistic_continuation`：已找到可执行的当前苹果到达方式，增长后又找到完整的8步乐观续路，不能称为长期安全路线。
- `route_postcheck_unknown`：找到苹果到达方式，但增长后的检查因预算或近满盘例外仍未知，不能当作通过。
- `route_wins`：吃当前苹果就满盘的候选，步数可能超过1。
- `no_qualifying_route_found`：预算内未找到满足上述条件的到达方式，不证明所有进食路径都不存在。
- `no_apple`：当前无苹果。

已有路线长度、即时出口数和尾部邻接仍记录，另新增：

- `postApple`：具体到达身体布局的后续检查。这里的moves从吃果后开始计，不包含吃果那一步；当场无出口为0。未知不填写死亡步数。
- `postAppleNodes`：该首方向的所有苹果到达检查累计访问节点数。
- `rejectedTrapArrivals`：已证明吃后困死而被拒绝的到达方式数量；拒绝的是候选到达身体，不是移除JEV的方向。

## 工作量与历史边界

进食搜索保留有界 best-first 的 `g + 16 × Manhattan` 顺序，结果只说明找到了某个候选，不承诺最短。发现一个吃后困死的端点后，继续尝试其他路径形成的身体排列。

困死搜索与苹果搜索仍各有每首方向2048状态预算。额外的增长后检查在同一首方向下累计共享2048节点，而不是每个苹果端点重新获得2048，避免乘法放大。队列和已访问集合也受限制；内存中只保留轻量几何，不复制历史请求树。预算耗尽完整记录为未知，不静默关闭分析。

字符图和每步观察仍保留，模型选择及原始概率原样执行和保存。未知未来食物、有限生存窗口和静态尾部连接都没有被描述为安全保证；没有通过自动走路、额外过滤已合法方向或强制结束对局来制造改进。
