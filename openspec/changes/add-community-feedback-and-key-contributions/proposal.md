## Why

当前站点只有观战与历史入口，观众无法在站内反馈或加入交流群；连续观战也只依赖站长配置的一把模型 Key，费用耗尽会影响持续运行。需要增加匿名反馈、企微入群和自愿贡献模型 Key 的完整入口，让验证通过的贡献真正接入连续观战。

## What Changes

- 顶栏增加“反馈”导航、“企微交流群”和“贡献 Key”按钮，保持首页、观战、历史入口和现有视觉风格。
- 新增 `/feedback`：游客免登录提交纯文本意见，保存成功后立即匿名公开；只展示内容与时间，不要求昵称、头像或联系方式。管理员可隐藏和重新展示反馈。
- 企微入口读取站点配置的真实入群链接或二维码；未配置时明确提示，不能显示虚构的入群成功。
- 贡献弹窗支持用户已确认的 Typesafe 和 OpenRouter，说明验证及后续观战会使用该 Key 产生费用；服务端实际调用对应 JEV 模型验证，成功后自动加密入库并启用。
- 贡献验证通过且成功入库后，弹窗展示感谢文案与一次短暂庆祝动效，明确告知 Key 已加入凭证池；减少动态效果时显示静态感谢状态。
- 连续观战引入可关闭的同服务商凭证轮换：配置的站长 Key 与已启用贡献 Key 按确定顺序轮换；明确的凭证失效或余额不足会停用该凭证，并在保留失败事实后尝试下一把。网络、限流、模型权限、格式和存储错误仍明确暂停，不跨服务商切换。
- 管理员沿用现有会话入口管理反馈、查看贡献 Key 的脱敏状态、禁用或重新验证凭证；贡献者可撤回自己的 Key。匿名反馈与贡献记录不关联，不建立贡献者公开榜单。
- 新增公共提交接口与私有管理接口，更新“游客只读”的适用范围：游客仍不能创建、控制或接管对局。
- **BREAKING（部署兼容）** SQLite 从当前 schema v2 事务迁移到 v3；部署贡献功能需服务端独立加密配置。旧后端不识别 v3，回滚不能静默降级数据库或删除历史。

## Capabilities

### New Capabilities

- `snake-feedback`: 匿名反馈提交、即时公开、列表读取与管理员隐藏。
- `snake-community-entry`: 企微链接/二维码配置及真实入群入口。
- `snake-key-contributions`: 明确授权、真实验证、加密存储、撤回、管理与同服务商凭证池。

### Modified Capabilities

- `snake-presentation`: 全站顶栏新增入口、弹窗及窄屏/键盘交互。
- `snake-owner-control`: 同一管理会话下新增反馈和贡献 Key 管理能力。
- `snake-server`: 明确公共贡献写接口与游戏控制权限的边界，持久化新业务记录。
- `snake-jev-runner`: 连续频道使用明确的凭证选择器，记录每次真实调用和凭证错误后的同服务商切换；CLI 维持原显式单 Key 行为。
- `snake-continuous-watch`: 凭证轮换、耗尽暂停、恢复和用户停止意图的一致性。

## Impact

- 前端：`src/components/Header.tsx`、新增反馈路由及贡献/入群弹窗、`src/features/snake/OwnerControl.tsx` 和相关样式；通过现有命令生成路由树。
- 服务端：`server/index.ts`、`server/start.ts`、`server/app.ts` 装配公共入口与管理服务；新增反馈/凭证模块，复用 `server/watch/owner.ts` 的会话，管理 API 保留在 `/api/watch-admin/*` 的 cookie 路径内。
- 模型运行：`server/jev/client.ts`、`config.ts`、`runner.ts` 与 `server/watch/channel.ts`/`store.ts`，保留响应单步、真实局面、原始请求正文和历史回放语义。
- 存储：扩展 `server/db/store.ts` 的版本迁移；新增反馈、贡献凭证、验证回执、私有调用记录和池状态，均不写入公开对局 JSON。
- 配置与验证：`.env.example`、`README.md`、相关 Vitest/HTTP/SQLite 回归和真实浏览器验收。复用现有 Solid、Hono、SQLite 和服务商传输，无需引入账号系统或外部存储服务。
- 范围外：登录与实名体系、反馈点赞/回复/附件、人民币捐款、账单结算、任意模型或第三个服务商、自动切换服务商、游客游戏控制。
