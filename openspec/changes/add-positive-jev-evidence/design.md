# 正向证据实现

## 计算

先复用冻结棋盘候选并逐步复验；否则以完整有序身体、朝向、已知苹果为节点，使用显式 DFS。固定障碍距离只影响搜索顺序。遇当前苹果终点或活动路径上的完整几何循环就产出存在见证；完全穷尽才报告 exhausted。未知食物不读取 RNG，不施加人工搜索预算。

状态转移使用 inspectMove 的真实碰撞/尾巴/增长规则。路线长度不承诺最短；吃后的空间来自该路线终点，不能替换成另一候选的 postEat。循环仅代表固定长度无增长循环，不证明苹果不可达。

## 传输与记录

模型收到四方向 opportunity 摘要、原有局面/进度事实；完整方向序列与原始几何在 decision.evidence 保存。provider body 与保存的 request 使用同一 JSON 字符串，后台 evidence 不加入 HTTP body。

witnessContinuity 对先前见证进行几何投影并与实际身体/方向/苹果/障碍/规则比较。相同端点可能来自不同动作序列，因此字段是 stateCompatibleAfterMoves；不推断模型意图或实际路径。仍相容的旧 record 一并保留，重复剩余路线按语义去重。

## 自主边界

四个方向固定顺序完整保留，即使某方向已证必死，JEV 返回它时也如实提交。无自动驾驶、方向覆盖、模型重试挑选、隐藏限步。回放区分实际模型输入与后台见证。

## 验证

真实529dd几何回归、独立真实引擎逐步重放、增长/满盘/尾巴释放/循环、版本schema、实际HTTP正文与档案分离、相容端点不等于相同前缀、旧历史读取。离线评估和模型fixture对照分开，有限fixture不声明整体胜率。
