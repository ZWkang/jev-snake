## MODIFIED Requirements

### Requirement: 对局摘要与历史查看

系统 SHALL 为每局分配唯一标识，记录参与者类型和显示名称、开始时间、推进模式及适用的开局速度配置、对局状态、分数、已结算步数、游戏有效时长、结束原因和记录完整性。历史按开始时间从新到旧展示，支持按实际参与者与结果状态筛选，并提供可回放记录的入口；无记录时显示真实空状态。首版不展示不存在的人类玩家筛选。

#### Scenario: 完整对局出现在历史中
- **WHEN** 一局已结束且记录持久化成功
- **THEN** 历史显示该局摘要，重新打开页面仍可查看，并可进入相同对局的回放

#### Scenario: 历史筛选和空状态
- **WHEN** 游客筛选一位参与者或一种结果，且不存在匹配记录
- **THEN** 显示该筛选的空状态，不展示虚构对局填充列表

#### Scenario: 混合展示两种模式
- **WHEN** 历史中同时存在 fixed、response 和旧 v1 对局
- **THEN** 可区分固定步频与随响应推进；response 显示基于已记录步数/有效时长的平均步频或无样本标记，不出现 Infinity/NaN 或虚构的 300ms/500ms 配置

#### Scenario: 等待中主动结束
- **WHEN** response 对局 start 后等待 10 秒但没有移动，随后控制者主动结束
- **THEN** 历史保留 0 步、未移动棋盘与实际已记录等待时长，不伪造撞墙或步数

### Requirement: 过程记录与保存结果可见

系统 SHALL 保存初始局面、规则/记录版本、实际随机生成结果、推进模式、适用的开局速度、实际移动间隔、控制请求的接纳/拒绝/生效结果、已提交状态变化、分数、有效游戏时间以及结束事件。只有成功持久化的内容可以标记为已保存；失败 SHALL 明确显示原因和最后已保存位置，不吞掉异常或显示虚假成功。

#### Scenario: 保存失败
- **WHEN** 一次持久写入失败
- **THEN** 页面明确提示记录未完整保存并保留最后已保存位置，不把后续未保存片段标记为可回放
