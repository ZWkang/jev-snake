# 历史 V13：合法选项与单步空间事实

当前默认入口已更新为 [V15 吃果后续路检查](jev-growth-space.md)。本页保留 V13 语义；`JEV_DYNAMIC_ANALYSIS=false` 可显式使用 V13。

V13 请求使用 `state.contextVersion = "legal-space-v13"`。参考 [sorrycc/typesafe-snake 的固定源码版本](https://github.com/sorrycc/typesafe-snake/tree/8bf3f7c261ad35ece3345a02d21ba638ddfaf87f)，采用合法方向过滤、每步空间事实和较短提示词，并适配本项目的障碍、星星、增长规则及历史存档。

## 请求结构

- `model`：继续使用环境配置的实际模型，没有切换供应商。
- `state`：规则、完整坐标与字符图、蛇身顺序、朝向、分数、苹果、星星、观察时间和真实进度历史；新增 `moveFacts`、`excludedMoves` 和事实定义 `factsSemantics`。不再发送 V12 的长篇 `strategyGuide`。
- `questions.direction.type`：`choice`。
- `questions.direction.instructions`：说明这是贪吃蛇、持续吃苹果并填满可行走区域的目标，嵌入本次观察的完整字符图与图例，然后说明出口、空间、尾部连接和进食之间的取舍。
- `questions.direction.criteria`：键为本步合法的绝对方向，值为字符串描述。包含目标坐标、相对转向、食物和移动后的空间事实。

请求构造位于 `server/jev/board-context.ts`，几何分析位于 `shared/snake/legal-space-analysis.ts`。碰撞判断与实际引擎共用 `shared/snake/move-rules.ts`，避免两套规则漂移。原始请求、响应和实际选择照常存档；回放保留字符图并展示当时发送的事实。

## 事实的中文含义

| 字段 | 含义 |
| --- | --- |
| `target` / `turn` | 本步目标坐标，以及相对当前朝向的直行、左转、右转。选项键仍为绝对方向。 |
| `eatsApple` / `eatsStar` | 本步是否到达当前苹果或星星。苹果增长一格；星星不增长，实际计分仍受过期时间影响。 |
| `appleDistance` | 目标与当前苹果的曼哈顿距离，不是绕过障碍的真实路线长度；吃到为 0，无苹果为 null。 |
| `lengthAfter` | 本步完成后蛇身长度。 |
| `freeCellsAfter` | 全图总格数减障碍数和移动后蛇长。 |
| `reachableFreeCells` | 本步完成后，从新蛇头出发可到达的静态空格数，不含头和其他身体格；苹果和星星所在格计为空格。 |
| `canReachTail` | 上述静态区域或新蛇头是否邻接移动后的尾格；不证明动态身体移动后一定能到尾巴。 |
| `nextLegalMoveCount` | 在移动后的身体位置检查紧接着下一步的合法方向数量；没有抽取未来苹果。新苹果只能出现在空格，不影响这次立即碰撞判定。 |
| `deadEndRisk` | 可达空格小于移动后蛇长，且没有静态尾部连接时标记风险；属于启发式，不是死亡证明。 |
| `terminal` | `board_complete` 表示本步填满所有非障碍格并获胜；否则为 null。获胜时无需后续动作，因此尾部连接和下一步出口均为 null，风险为 false。 |
| `excludedMoves` | 本步被排除的方向及原因：reverse、wall、obstacle、body。非增长时腾空的尾格可以进入。 |

每个合法方向只投影一步完整身体，再迭代遍历静态空域。分析不执行多步路径搜索、不预测未来食物、不修改局面或 RNG。每个方向的时间与空间开销均为 O(棋盘面积)。

## 提示词的决策要求

1. 若某步立即填满棋盘，识别为获胜，不因没有出口而避开。
2. 若还有可继续移动的选项，避免 `NO_NEXT_MOVE`（执行本步后确实没有合法下一步）。
3. 把 `DEAD_END_RISK` 当静态风险，结合字符图、身体顺序、可用空间和尾部连接比较候选。
4. 持续寻找可行的进食方式；使用真实历史识别没有吃果的重复绕行，不能只追求最大面积。
5. 只返回一个实际提供的绝对方向。静态空间和曼哈顿距离都不构成长期安全路线。

合法但未来危险的选项仍交给模型选择。程序只排除当前一步已经违反游戏规则的方向，不按空间分数替换模型选择。

## 已知失败帧示例

对局 `4b11be01-0847-4462-9b7a-3a6764cb4921`，观察第 218 步、准备第 219 步（观察事件 441），原模型给向下 51%。新分析从完全相同的身体和地图得到：

| 选项 | 移动后可达空格 | 下一步合法出口 | 静态尾部连接 | 标记 |
| --- | ---: | ---: | --- | --- |
| 向上 | 19 | 1 | 有 | 未触发空间风险；并非长期保证 |
| 向下 | 0 | 0 | 无 | NO_NEXT_MOVE、DEAD_END_RISK |

向下这一格本身没有碰撞，所以仍在选项中；其后无出口的事实直接写入选项。这样可以检查 JEV 是否真正利用事实，而不把程序代选算作模型改进。

## 执行与历史边界

只剩一个合法方向时仍真实调用 JEV，保存服务商返回的选择、概率和置信度；概率为 1 不代表模型完成了复杂推理。没有任何合法方向时沿用现有 `no_legal_moves` 终局，不进行无意义请求。

没有移植参考项目的超时直行或报错自动选择。调用失败、额外概率键、缺失概率键或返回未提供方向都会显式报错。保留原始概率，不补零或重归一化。V12 的三个选项和更早版本的四个选项按各自历史协议读取，不修改旧请求。

可达空间能减少部分明显判断失误，仍无法保证避免多步死胡同、持续吃果或通关。固定帧选择、有限窗口存活与整局胜率需要分别报告。
