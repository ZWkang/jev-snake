# V16：精简实时决策请求

实时默认使用 `compact-growth-v16`，增长与困死判断沿用 [V15](jev-growth-space.md)，当前实时寻果深度为 128 步，其他预算不变。`JEV_DYNAMIC_ANALYSIS=false` 仍显式使用 V13。

每步请求删除 `state.rules`、`state.factsSemantics`、`state.dynamicSemantics` 三段重复说明，核心游戏规则和分析边界集中在较短的 `questions.direction.instructions`。`criteria` 的键和值均为方向名，具体方向事实只在 `state.moveFacts`、`state.dynamicFacts` 记录。

保留完整棋盘、字符图与图例、头到尾身体顺序、食物、观察与目标步数、真实进食/重复历史、全部方向事实和搜索预算。字符图与图例仍在 instructions，也在 state 中保留供一致性校验和回放使用。没有截取地图、丢弃身体、截断请求。初版 V16 仅精简格式；下述长绕行改动另行扩大了实时寻果深度。

短说明仍区分证明困死、有限窗口续路、吃果后不再增长的乐观条件、预算耗尽和近满盘未知；未找到合格苹果路线不能当作苹果不可达。静态面积及曼哈顿距离不能推翻困死证明。模型继续决定每个实际动作，不把单一选项变成本地代选。

V16 使用独立归档校验。校验过程临时复用 V15 的事实约束，不重新执行动态搜索；临时补充的说明不写入原请求或解析输出。旧 V15 记录按原格式读取。回放中的中文字段解释明确属于界面说明，原始 JSON 和复制内容始终是当时实际发送的请求。

## 长绕行候选与跨步复核

实时入口使用 `liveGrowthLimits`：`appleDepth=128`、`trapDepth=8`、`postAppleDepth=8`、`maxNodesPerSearch=2048`。历史 V15 的独立构造器仍默认 32 步；已保存请求按当时的 `analysisLimits` 读取，不重新计算或改写历史。

每个 runner 独立持有 `GrowthRouteMemory`，仅缓存已经找到并通过检查的当前苹果候选。模型实际动作与某条候选首步相符、身体排列和苹果仍匹配时，将剩余路线作为下一次搜索优先复核的分支。它必须重新逐步通过真实移动规则以及吃果后的检查，节点计数仍受同一预算约束，不直接复用旧安全结论。其他方向仍完整提供各自的分析，不移除合法选项。

模型偏离未有见证的方向、吃果、跳步、换局或棋盘不匹配时重新搜索。缓存只属于 runner 生命周期，重启后从当前真实局面重建；不修改游戏状态、RNG、历史或恢复协议。星星不影响增长几何，过期不让已验证的身体路线失效；静态星星事实始终来自本步观察。

提示词在后续检查质量相当时优先比较 `apple.moves`，允许先绕行整理身体。候选长度不是最短路证明，乐观续路仍不是未来增长下的安全保证。完整路线留在程序内部，每步提交的方向和概率继续来自真实模型。

费用保护独立于寻路证据。历史分支继承无果步数，验证长绕行时必须显式记录使用的保护配置；扩大视野本身不延长或关闭保护。
