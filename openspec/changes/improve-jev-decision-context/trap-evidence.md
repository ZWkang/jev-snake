# 分叉死路证据优化

2026-09-19。来源：用户分析对局 `d6eb8e35-4828-4191-804f-8525055538b3` 后要求优化，并明确要求保留模型智能和最终选择权。

## 行为

- 四个方向、十六个方向对全部保留；选择、概率及执行协议不变。不添加自动改选、路线控制、重试或运行步数上限。
- 保留 `forcedPath` 遇到分叉即停止的含义，新增独立的封闭区域证明。证明以紧凑数据附在现有 `questions.*.instructions` 中，不改变 v3 请求结构或重算历史正文。
- 仅对已证明的封闭区域给出必死结论。面积小、静态不可达、尾部不连通，单独均不足以证明死亡；未能证明也不等于安全。
- 吃已知苹果后，若棋盘未完成且四方向都碰撞，`forcedPath` 返回 `forced_collision`，步数包含下一次致死尝试。若仍有出口，继续返回 `unknown_after_apple`，不预测随机新食物。
- 两步模式分别标记第一步和已知条件下的第二步。第一步增长后不构造未知的第二步位置。

## 证明及边界

在候选动作执行后的局面，以完整身体和障碍阻挡，搜索包含蛇头的静态连通区域：

- `A = regionCells`，包含蛇头。
- `L = bodyLength`。
- 初始身体第 `i` 段（头为 0），最快能在 `L-i` 次不增长的移动后被进入；增长只会延后这个时刻。
- `T = boundaryReleaseLowerBound`，区域相邻身体段的最早释放下界，以 `L` 初始化。

当 `A < L` 且 `T > A`，区域内最多容纳 `A-1` 次额外移动；再次进入新走过的身体前无法等到边界腾开。无论内部如何分叉，都不能逃出。`T == A` 必须保持未证明，因为最后一步可能恰好进入腾开的身体格。

还必须有空格位于区域外：若区域包含所有剩余空格，连续增长可能先填满棋盘获胜，不能据此判死。算法是一次完整的棋盘遍历，复杂度为棋盘格数的线性量级，没有任意深度、节点或耗时截断。
