## MODIFIED Requirements

### Requirement: 正交移动与合法方向

系统 SHALL 在 按开局配置的矩形棋盘（默认 24 列 × 18 行）上逐格正交移动，初始长度为 4，初始向右。控制动作只使用上、下、左、右四个方向；直接反向和非方向值必须明确拒绝，不当作成功动作。固定模式的方向只在定时移动边界生效；响应模式在当前局面的有效动作被服务端提交时立即移动一格。一次动作不得额外移动多格。游客的方向键或 WASD 不提交这些动作。

#### Scenario: 合法转向
- **WHEN** 蛇向右移动并且服务端接受上方向作为下一移动的方向
- **THEN** 下一移动只向上一格，局面和对应结果按相同顺序记录

#### Scenario: 禁止直接反向
- **WHEN** 当前方向为右，控制者请求直接向左
- **THEN** 返回明确的非法动作结果，不凭该请求改变方向、分数或局面

### Requirement: 固定节拍持续移动

在 fixed 模式下，创建请求 SHALL 支持正整数 `tickIntervalMs`，默认 300ms，速度显示为 `1000 / tickIntervalMs` 格/秒；本局启动后保持该配置。运行中每到一个计划移动时刻走一格，即使没有 Agent 新动作也沿原方向移动，不等待模型完成。不因游客帧率、观众数量或控制 WS 断线改变节奏。

#### Scenario: 没有新指令仍持续移动
- **WHEN** 默认速度的对局已开始，前 1200ms 内没有新指令且没有碰撞
- **THEN** 在 300、600、900、1200ms 分别推进，累计走 4 格

#### Scenario: 改变测试速度
- **WHEN** 创建下一局并设置 `tickIntervalMs` 为 500
- **THEN** 新局每秒走 2 格，已有对局及其回放记录不变

#### Scenario: 保留固定模式
- **WHEN** 创建请求未指定推进模式，或明确指定 fixed
- **THEN** 继续按开局固定间隔移动，不因本次新增模式变成等待模型

### Requirement: 计划转向与截止时间

Agent 方向请求 SHALL 明确指定 `targetTick`，只允许当前实际局面的下一次移动（targetTick = 当前 tick + 1），并必须携带当前实际局面摘要与所属 observedSeq。旧观察不得重新绑定到新 tick，不允许预判后连续排队多个未来动作。fixed 请求必须在目标计划时刻之前到达服务端消息处理入口；恰好或晚于目标时刻拒绝为 `late_action`，不顺延。response 没有基于耗时的移动截止，等待任意时长不使仍匹配当前局面的结果过期；已推进的观察、错误目标或失效摘要仍必须拒绝。执行前实际局面与预期摘要不同则标记 `stale_state` 并取消，不挪到其他位置执行。fixed 的同一 tick 只接收第一个合法方向请求，其余不同请求拒绝为 `tick_action_conflict`；response 的同一观察位置最多应用一次移动，后续旧位置请求必须拒绝；同 requestId 的重发使用去重结果。

#### Scenario: 截止前转向
- **WHEN** fixed 的目标 tick 1 时刻为 125ms，合法上方向在 100ms 到达且该 tick 没有已接受动作
- **THEN** 先确认 accepted，125ms 才向上走一格并记录 applied，不在 100ms 额外移动

#### Scenario: 恰好或晚于截止时间
- **WHEN** fixed 中针对 tick 1 的方向在 125ms 或 150ms 到达
- **THEN** 按原已接受方向或原行进方向结算 tick 1，请求被明确拒绝，不改写 tick 1，也不当作 tick 2 的方向

#### Scenario: 同一步连续快速请求
- **WHEN** fixed 中蛇向右，在同一截止前先收到合法向上，再收到不同 requestId 的向左
- **THEN** 第一个方向占据下一 tick；第二个明确冲突，不通过多次输入在同一 tick 反向

#### Scenario: 很慢但局面仍有效的响应
- **WHEN** response 对局在观察后等待了 10 秒，目标仍为当前 tick + 1 且局面摘要未变化
- **THEN** 不因等待时长拒绝该动作，原子应用一次移动；不得假装存在已错过的固定截止时间

#### Scenario: 两个结果引用同一位置
- **WHEN** response 对局收到两个不同 requestId、都引用第 N 步并请求目标 N+1 的动作
- **THEN** 最先提交的合法动作只推进一次，第二个动作因为观察已经推进而被拒绝，不能自动转成 N+2

### Requirement: 有效时间与服务异常

两种模式的游戏有效时间 SHALL 随运行中的服务端时间推进，包含等待模型的时间，星星 8 秒按该时间计算而非按 Agent 请求次数计算。控制者停止则记录 interrupted；服务端进程停止后再启动，原 running 局以最后已提交位置记为 interrupted，原因是 server_restart，不补跑停机时段、不伪造碰撞。ready 局仍保持未开始。

#### Scenario: 模型思考期间星星过期
- **WHEN** 星星已存续 8 秒运行时间且未被吃到，即使期间没有新方向请求
- **THEN** 星星按时过期；如果同一时刻也发生移动，先过期再结算移动

#### Scenario: 服务端重启
- **WHEN** 一局 running 时服务进程停止，随后从同一数据库启动
- **THEN** 保留最后已确认局面，追加服务中断结果，未生效动作标明 cancelled，游客可回放至该位置

#### Scenario: 响应等待期间奖励到期
- **WHEN** response 对局未移动但星星到达 8 秒有效期，且此刻收到动作
- **THEN** 先记录星星到期，再校验动作；已过期奖励不能被吃到，引用旧奖励摘要的动作拒绝且不移动，调用者可重新读取当前局面

### Requirement: 游客查看不影响运行

服务端对局 SHALL 独立于游客浏览器运行。游客隐藏标签、关闭页面、断开更新、暂停回放或改变回放倍速，均不能改变对局推进、原局速度、奖励时限或控制权。

#### Scenario: 所有游客离开
- **WHEN** 最后一位游客关闭观战页面
- **THEN** fixed 对局继续按节拍移动；response 对局继续按控制者有效响应推进或等待下一响应，均不因缺少观众改变规则或结束

## ADDED Requirements

### Requirement: 开局选择响应驱动模式

创建方 SHALL 可显式选择 stepMode=response，开局后模式不可修改。response 不配置固定移动间隔；显式同时给出固定步长的冲突配置必须报错。start 后，等待期间蛇的位置、方向、长度、步数和分数保持不动；只有当前实际局面的有效动作到达并提交才走一步。不得添加最低间隔、固定轮询步频、自动直行、旧动作重用或额外 sleep 来控制速度。游戏原有碰撞、得分、增长和满盘规则仍适用。

#### Scenario: 按到达时间移动
- **WHEN** 三次有效动作分别在服务端运行时间 120ms、470ms、1770ms 到达，且前一次已经应用
- **THEN** 分别在这些收件时刻结算第 1、2、3 步，记录真实间隔，不量化到 300ms、500ms 或其他固定网格

#### Scenario: 接口一直没有可用结果
- **WHEN** response 对局 start 后尚无有效方向，或控制者连接中断
- **THEN** 不发生任何自动移动；状态保持等待下一动作，已确认的停止或进程中断仍正常终结该局

#### Scenario: 非法反向
- **WHEN** response 对局向右，模型返回直接向左
- **THEN** 明确拒绝并记录该结果，蛇保持原位置；不得自动替换成向右或其他方向

#### Scenario: 与固定步长参数冲突
- **WHEN** 创建方显式指定 response 并同时指定正数 tickIntervalMs
- **THEN** 创建失败且不留下新对局，不静默忽略用户给出的冲突配置
