## Purpose

让观众自愿贡献 Typesafe 或 OpenRouter 凭证，在明确验证和持续观战用量授权后由服务端验证、保存并实际用于连续观战，同时提供撤回、管理、错误可见性和严格的凭证隐私边界。

## ADDED Requirements

### Requirement: 明确贡献授权和服务商选择

顶栏贡献弹窗 SHALL 允许选择 Typesafe 或 OpenRouter，并输入该服务商的 Key。提交前 MUST 清楚说明验证会发起一次真实 JEV 请求，成功后自动启用并用于本站连续观战、可能持续消耗账户余额，本站不承诺固定费用或额度；需用户主动确认授权。输入 MUST 不写入 URL、浏览器持久存储、统计埋点或反馈正文。成功、关闭弹窗和组件卸载时 SHALL 清除客户端持有的 Key。

#### Scenario: 未确认授权
- **WHEN** 用户输入 Key 但未确认验证与持续使用授权
- **THEN** 不发起验证请求，直接构造未授权请求也被服务端拒绝

#### Scenario: 选择服务商
- **WHEN** 用户选择 OpenRouter 并提交
- **THEN** 该 Key 只发送给本站服务端及配置的 OpenRouter 验证端点，不试投 Typesafe 或游客提供的地址

### Requirement: 真实模型验证和自动启用

系统 SHALL 使用所选服务商配置的 JEV 模型进行一次不改变真实对局的结构化决策验证，校验 HTTP 成功、响应结构、返回选项及概率字段契约。只有校验成功且凭证与回执持久保存成功后 SHALL 返回“验证通过，已加入凭证池”。不允许仅凭前缀、余额查询或 HTTP 200 判定可用。失败 SHALL 区分鉴权、额度、限流、权限、网络、格式和保存错误，不能进入可用池。

#### Scenario: 真实验证通过
- **WHEN** 对应 JEV 模型返回合法结构化结果且数据库提交成功
- **THEN** 自动启用该凭证，返回验证时间和待调度状态；不将验证结果提交为游戏动作

#### Scenario: HTTP 成功但结构错误
- **WHEN** 服务商返回 HTTP 200，正文却缺少合法选择或概率字段
- **THEN** 验证失败且不启用，页面不显示验证通过

#### Scenario: 验证成功但入库失败
- **WHEN** 真实调用有效但保存凭证或回执失败
- **THEN** 返回保存失败，不将只在内存中的 Key 投入运行，也不宣称贡献成功

### Requirement: 验证幂等和不确定结果

同一贡献请求 SHALL 去重，重复提交或查询不得重复计费验证，同一服务商同一 Key 不得创建多个池成员。同请求标识不同内容 SHALL 冲突。验证结果丢失或服务重启导致结果不确定时 MUST 标记为未确认，不自动补发真实验证；用户显式重试前 SHALL 知道上次可能已产生费用。已被管理员禁用的凭证不能通过普通重复投稿重新启用。

#### Scenario: 重复点击贡献
- **WHEN** 相同请求正在验证或已经完成，用户再次发送相同请求
- **THEN** 返回原验证状态或回执，不并发调用或创建第二条凭证

#### Scenario: 验证期间重启
- **WHEN** 已登记验证请求，但服务重启时没有已提交的完成结果
- **THEN** 结果标为未确认且不进入可用池，不自动重新验证

### Requirement: 凭证隐私和持久化

凭证 SHALL 只以可验证完整性的密文持久保存，加密主密钥与数据库分离；生产环境的贡献传输 MUST 使用 HTTPS。业务接口及日志 MUST 不返回原始 Key、密文、可用于关联贡献者的指纹或可恢复秘密。管理员仅能读取随机内部编号、服务商、掩码、状态、验证与调用时间及脱敏错误。公开游戏数据只能展示服务商和模型，不能展示凭证标识。密钥缺失、解密失败或存储失败 SHALL 明确暴露，不能降级明文存储。

#### Scenario: 检查公开历史和日志
- **WHEN** 验证、运行或错误响应中涉及贡献 Key
- **THEN** 页面、HTTP/WS 公开数据、对局事件及应用日志均不包含原始 Key、密文和贡献者标识

#### Scenario: 加密配置失效
- **WHEN** 服务器无法解密已登记的贡献凭证
- **THEN** 显示配置错误并停止依赖该配置的贡献/池操作，不改用明文或假装没有贡献

### Requirement: 确定性的同服务商凭证轮换

启用凭证池时，连续观战 SHALL 仅使用当前明确选定服务商及模型可用的凭证，包含已配置站长 Key 和验证通过的启用贡献 Key。正常轮换 SHALL 发生在局间，按稳定顺序逐局轮换；局内固定当前凭证，直到明确失效、余额不足、禁用或撤回。只有确认属于凭证鉴权或额度耗尽的错误 SHALL 排除该凭证并选择下一把；限流、临时预算阻塞、权限、网络、配置、解析和存储错误均不能借轮换绕过。所有切换 SHALL 留下脱敏原因和真实调用记录，不跨服务商或自动换模型。关闭池模式后 SHALL 恢复原有站长单 Key 行为。

#### Scenario: 两把有效 Key
- **WHEN** 同服务商有 A、B 两把可用 Key，连续进行两局
- **THEN** 第一局使用 A，下一局使用 B；验证调用不计为一局、不推进正常轮换顺序

#### Scenario: 确认余额耗尽
- **WHEN** 当前 Key 收到可明确判断为余额耗尽的响应且同服务商还有下一把
- **THEN** 保存失败及停用状态，切换下一把，不重复请求已耗尽 Key，不隐藏此次失败

#### Scenario: 临时限流或不明错误
- **WHEN** 当前请求被限流、临时预算阻塞或错误无法确定为 Key 失效/余额耗尽
- **THEN** 保留错误并暂停频道，不换 Key 绕过限流，也不误标该 Key 永久失效

#### Scenario: 只有另一服务商的 Key
- **WHEN** 当前选定 Typesafe，而只有 OpenRouter 贡献 Key 可用
- **THEN** 提示当前服务商没有可用凭证，不自动更换服务商；该贡献保持已验证但未被当前频道调度的状态

### Requirement: 撤回和管理员禁用

贡献者 SHALL 能通过再次提供原服务商及完整 Key 撤回贡献，无需公开身份，撤回不得产生模型调用。管理员 SHALL 能禁用、重新验证并启用贡献 Key。撤回或禁用确认之后 MUST 不再用该 Key 发起新的观战调用，只有明确的重新验证授权允许验证调用，且验证通过前仍不用于观战。已有在途调用可能已经计费，不承诺撤销该费用；已发出调用可完成并按原观察规则提交，随后重新选择凭证。撤回 SHALL 清除活动密文；管理员不能直接恢复已撤回且没有 Key 的记录。

#### Scenario: 在模型等待期间撤回
- **WHEN** 贡献者撤回当前使用的 Key，已有一个请求在途
- **THEN** 撤回被持久记录，不再发起新调用；已发出的请求照原规则完成或失败，下次调用换用可用 Key，没有可用 Key 则明确暂停

#### Scenario: 管理员恢复停用凭证
- **WHEN** 管理员明确请求重新验证被停用但仍保存密文的凭证
- **THEN** 只在真实验证成功并保存后启用，验证失败保留停用和错误信息
