# 多出口与增长后死亡证明修复

2026-09-19。针对真实对局 `27c656f4-912e-451b-be64-2b6a7fa2381d` 在第1155步撞身结束，以及旧分支第1630步向左进入死路的漏判。

## 根因与修复

旧分析器遇到两个需要更深证明的出口就返回未知；吃苹果后的证明也只能沿唯一通道检查。两者叠加，使入口未标危险，进入之后才发现所有出口都必死。

- 显式栈检查全部合法出口，只有每条出口都有有限死亡证书才合并结论；重复的已完成子证明复用，只有当前路径重复才视为循环。
- 动态验证蛇头到尾部、再沿原身体返回的完整闭环。只有身体与方向完全复原且未吃苹果才构成循环见证，用于停止必死求证，不控制游戏动作。
- 吃已知苹果后，以未来不再增长的乐观几何求证全部分支。真实增长只会保留更多身体；若该乐观局面仍必死，且空格数 `F >= B`（碰撞上界包括致死尝试），则排除了最多 `B-1` 次成功移动内先填满棋盘的可能。
- 未证明的增长后续、循环或胜利仍保持未知，不读取未来随机奖励。没有深度、节点数、耗时或对局步数上限，也没有方向过滤、排序、改选或错误后自动换模型。
- 单次请求的动作事实、第二步事实和证明文本共用 analyzer；缓存键包含棋盘、障碍、苹果、有序身体和方向。摘要复用共享子证明计数，保留原展开计数语义；不可精确表示的计数与循环证书明确报错。
