# V14 动态分析存档合同

`dynamic-space-v14` 保留 V13 的原始棋盘和一步静态事实，另存每个合法方向的 `dynamicFacts`、本次真实使用的 `analysisLimits` 与 `dynamicSemantics`。各搜索的步数包含候选首步，节点预算独立使用。找到的路线长度不等于最短路线；`node_limit`、`horizon_reached` 和未找到路线都不是安全证明。`board_complete` 可以表示若干步后的获胜续路，本步真正填满棋盘时才是 `moveFacts.terminal=board_complete`。

归档 schema 验证原始几何和静态事实、合法选项集合、动态字段类型与互斥关系、预算范围、访问节点与步数的必要关系、食物距离的必要条件，以及可直接由第一步确认的死亡或获胜结果。概率只允许请求实际提供的方向，旧版本仍按原版本读取，不补动态字段、不迁移或改写历史请求。

**归档解析不重新运行动态搜索，也不能证明所有动态结论的算法正确性。** 回放和 SSR 会反复解析大量事件，不能让每次读取都展开搜索。`proven_trap` 的完整分支检查以及远期食物路线的真实性由产生它们的分析器和真实几何回归测试负责；schema 只能拒绝结构不合法、越预算或与已知一步事实矛盾的声明。搜索预算耗尽必须归档为未知，不能伪装成死亡结论。

`analysisLimits` 接受正整数的显式预算，而不是强制等于当前线上默认值，以便原样保留较小预算的测试和未来配置。这个读取合同不会改变线上 builder 使用的默认预算。
