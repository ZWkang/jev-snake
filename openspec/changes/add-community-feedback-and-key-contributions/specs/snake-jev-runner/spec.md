## MODIFIED Requirements

### Requirement: 模型结果可追溯

系统 SHALL 保存实际模型、单步选择、概率、置信度、请求耗时及接纳/生效结果，每个新移动关联真实单步请求，不生成备用或直行来源。旧计划历史 SHALL 保留一次请求与两步生命周期及联合概率的原有含义，不重复计算调用。失败 MUST 暴露原因，不返回假成功、不换模型。仅连续频道显式启用凭证池且错误符合 snake-key-contributions 的凭证失效/余额耗尽规则时，SHALL 在保存失败事实和排除该凭证后，以同服务商的下一把凭证重新读取实际局面再请求；不能把失败记为模型决策。CLI 和关闭池模式仍 SHALL 在 API 错误时退出并中断。

#### Scenario: API 失败
- **WHEN** 服务商、网络或响应格式发生真实错误，且不符合显式凭证轮换条件
- **THEN** runner 暴露错误、非零退出并通过受保护通道中断尚在运行的对局，保留已提交历史

#### Scenario: 真实错误与终局相邻发生
- **WHEN** 已发生终局但请求返回真实 API、网络或格式错误
- **THEN** 仍报告失败，只有与实际 abort reason 相同的错误才归为主动取消；终局后不因凭证轮换再发请求

#### Scenario: 请求在结束前未完成
- **WHEN** 对局结束时模型请求尚未返回
- **THEN** 记录开始与取消、观察步、目标步及真实等待时长，不虚构模型决策

#### Scenario: 同一目标前凭证失效
- **WHEN** 连续频道当前 Key 明确鉴权失败且有下一把可用凭证
- **THEN** 记录原调用失败，保持当前局不移动，重新读取局面后串行请求下一把，只有后续有效结果才能推进一次

## ADDED Requirements

### Requirement: 轮换不改变响应单步语义

凭证选择与切换 SHALL 保持每局最多一个外部模型请求在途；前一调用必须完成并记录后才允许下一次。每次重新询问 SHALL 读取当前真实局面、进度、观察序号和状态摘要，失败不消耗游戏 RNG、不补步、不继承旧请求目标。已确认动作的网络重发仍 SHALL 使用原 requestId，不能因凭证轮换重复提交。凭证标识仅进入私有调用记录，模型原始 HTTP 正文和公开回放不增加凭证字段。

#### Scenario: 换 Key 时奖励过期
- **WHEN** 第一次调用因 Key 失效失败，切换前可见奖励已经变化
- **THEN** 新请求使用重新取得的局面和摘要，不能把旧正文改绑到新观察

#### Scenario: 游戏已确认但回执丢失
- **WHEN** 有效动作已提交，而客户端未收到游戏回执
- **THEN** 按原请求去重语义获取结果，不重新调用另一把 Key 再推进同一步

#### Scenario: 私有调用记录失败
- **WHEN** 无法保存一次调用的开始、结果或凭证切换记录
- **THEN** 明确报告存储故障并停止后续调用，不把缺少持久记录的结果当成成功或继续消耗下一把 Key
