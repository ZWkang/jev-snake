## MODIFIED Requirements

### Requirement: 公开读取与受保护控制

服务 SHALL 使用 HTTP 提供公开的对局列表、单局状态、历史和回放查询，以及受保护的创建对局接口；使用 WebSocket 提供受保护的 start/action/stop、请求确认和游客只读观测通道。游客读取不改变游戏状态。HTTP 与 WebSocket 均按对应角色验证游戏控制权限，游客不能通过修改请求或消息取得游戏写权限；控制密钥不出现在公开响应、事件、前端构建、URL 或日志中。反馈投稿、Key 贡献及持有原 Key 的贡献撤回 SHALL 是独立、明确的公共写入能力，不授予任何游戏或管理员权限；这些浏览器写接口 SHALL 校验本站 Origin、输入结构及明确的请求体安全限制，不能将“公共投稿”当作任意管理写接口的豁免。

#### Scenario: 无控制凭证写入
- **WHEN** 请求没有合法控制凭证或凭证不属于目标对局
- **THEN** 返回明确的未授权/禁止响应，不修改状态、分数或事件

#### Scenario: 读取实时局面
- **WHEN** 游客读取进行中对局及其事件流
- **THEN** 获得公开局面与顺序事件，不获得控制密钥，也不因读取推进游戏

#### Scenario: 投稿后尝试控制游戏
- **WHEN** 游客成功提交反馈或贡献 Key，随后调用创建、转向、停止或管理接口
- **THEN** 投稿回执不被当作控制凭证，受保护接口仍拒绝未授权请求

#### Scenario: 非本站发起公共写入
- **WHEN** 公共投稿、贡献或撤回请求的 Origin 不匹配本站配置
- **THEN** 明确拒绝，不写入记录或发起模型调用

## ADDED Requirements

### Requirement: 社区业务存储与历史隔离

反馈、验证回执、贡献凭证和私有调用记录 SHALL 持久保存，成功确认以实际事务提交为准。数据库升级 SHALL 保留原对局、事件、频道及请求去重记录，不重写已保存模型请求。未知版本、迁移错误和写入失败 MUST 明确暴露，不删除数据、不切换空库；新业务记录不得混入公开对局事件以泄露贡献身份或凭证。

#### Scenario: 从已有数据库升级
- **WHEN** 数据库包含历史对局及未完成频道并执行社区功能升级
- **THEN** 旧记录标识与正文不变，新表可用，已有频道仍按真实保存的状态恢复

#### Scenario: 升级过程失败
- **WHEN** 新业务表或迁移版本提交失败
- **THEN** 迁移事务回滚，服务报告失败，不确认部分迁移成功
